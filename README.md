# Job Radar

국내 IT 기업의 **AI·백엔드·풀스택** 채용공고 중 **경력 기준선을 넘는 것만** 모아
요약한 보드다.
[`sojw/AhnChangHo`](https://github.com/sojw) 의 `job-watcher` 가 생성해 force-push 한다.

- 요약은 **공고 원문 발췌**다. 문장을 생성하지 않는다(LLM 을 쓰지 않는다).
- 판정은 **직무명 기준**이다. 본문까지 보면 '우대사항: Kubernetes 경험' 하나로
  백엔드 공고가 인프라로 탈락한다.
- `BE/FE 개발` 처럼 겸업 공고는 **백엔드**로 본다. 풀스택·프로덕트 엔지니어는 **풀스택**이다
  (2026-10-25 에 열었다). 프론트엔드 전담 공고는 같은 날 보드에서 내렸다.
- **연차는 수집이 가른다 — 화면에는 조건이 없다.** 요건의 **상한**으로 거르고
  (`10년차 이상 시니어`가 지원할 수 있는 것만), 상한을 모르는 공고는 버리지 않고
  `미상` 으로 표시한다. 화면에 남은 연차 조건은 `연차무관` 토글 하나다 — 끄면
  경력을 아예 안 적는 Greenhouse·토스가 통째로 사라진다.
  (2026-10-17 까지는 화면에도 슬라이더가 있었다. 수집은 **상한**, 화면은 **하한**을
  봐서 같은 페이지의 두 숫자가 다른 뜻이었고 세 번 잘못 읽혔다. 자세한 것은
  `job-watcher/README.md` 의 대시보드 절.)
- 같은 공고가 여러 소스에 올라오면 **회사가 직접 올린 쪽**을 남긴다.
- 「지난 방문 이후」 는 **마지막으로 본 시점**과 공고를 처음 본 날을 견준 것이다.
  읽었는지 여부는 기록하지 않는다 — 서버가 없다.
- **정렬은 두 가지다.** 기본 `회사별` 은 회사를 **매출 내림차순**(`companies.csv`
  의 rank, 79곳)으로 세우고 랭킹 없는 206곳을 뒤에 붙인다 — 뒤쪽 순서는 의도한
  것이 아니라 `key=(rank, title)` 에서 rank 가 다 같아 생긴 부산물이다. 회사 안은
  제목 가나다순. `최신순` 은 회사 묶음을 깨고 564건을 **처음 수집한 시각** 내림차순
  한 줄로 세운다. 정렬은 이 브라우저에만 저장한다 — 계정에 올리려면 Firestore
  규칙의 prefs 키 목록을 같이 늘려야 한다.
- 「최근 등록된 공고」 는 방문과 무관하게 **처음 수집한 날이 늦은 순**이고,
  **AI·백엔드 20건 / 풀스택 20건**을 따로 센다. 한 묶음으로 두면 그날 많이
  들어온 직군이 목록을 다 먹는다 — 프론트엔드를 열었던 날 최근 30건이 전부
  프론트엔드였다. 직군 칩을 고르면 해당 트랙만 남는다.
  날짜는 공고사가 올린 날이 아니라 **우리가 처음 본 날**이라 요약 줄에
  '… 수집' 으로 적는다. 데이터(`f`)에는 **분까지** 들어 있다 — 수집이 하루 세 번
  (09:00·13:00·18:00)이라 날짜만으로는 같은 날 들어온 수십 건의 선후가 안 갈린다.
  `최신순` 정렬에서는 그대로 쓰고, 요약 줄에서만 날짜로 줄인다.
  `최신순` 일 때는 이 묶음을 띄우지 않는다 — 목록 맨 위를 그대로 되풀이한다. 하루에 60건 넘게 들어오는 날이 있어 20건이 한 날짜에 다
  들어가므로, 그 안의 순서는 회사·제목으로 고정한다 — 안 그러면 다시 그릴 때마다
  20건이 달라진다.
  위 「지난 방문 이후」 에 이미 나온 공고는 빼고, 회사별 묶음과는 일부러 겹친다.
- **☆ 즐겨찾기는 Google 로그인이 필요하다.** 계정에 저장돼 다른 기기에서도 보인다.
  저장하는 것은 공고 주소 목록과 **조회조건**(직군·연차무관)뿐이다. 소스 칩은 2026-10-25 에 뺐다.
  검색어와 선택한 회사는 올리지 않는다.
